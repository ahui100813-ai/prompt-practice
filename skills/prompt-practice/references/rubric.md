# 评分与领域检查

收到用户提示词后再评分。评价表达是否足以完成当前任务，不评价用户水平、人格或提示词长短。以下尺度用于学习反馈，不是经实验校准的模型能力指标。

## 五维 20 分

每维给整数 0—4 分，合计 20 分。对同一题目的初稿和改稿用相同的维度、任务要求和尺度。可以报告分数变化，但不能把分数提升等同于真实效果提升。

| 分数 | 通用锚点 |
| --- | --- |
| 0 | 缺失，或与题目要求直接冲突 |
| 1 | 只有笼统表述，无法据此确定关键要求 |
| 2 | 已有可执行信息，但仍缺影响结果的关键内容 |
| 3 | 对本题已充分、明确，只有一处有实际影响的小缺口 |
| 4 | 对本题充分且一致，没有发现需要补充的相关内容 |

不要为了给满分要求多余细节。简单任务没有复杂流程也可以得 4 分。

| 维度 | 要判断的内容 | 低分线索 |
| --- | --- | --- |
| 目标 | 做什么、交付什么、服务谁或什么用途 | “帮我弄一下”“更好看”，缺具体任务 |
| 背景与资料 | 所需事实、输入材料、现有上下文与资料边界 | 缺活动事实、未提供代码、要求编造资料 |
| 约束 | 必须遵守的限制、优先级、禁止内容和冲突处理 | “专业一点”，约束相互矛盾或超出范围 |
| 输出形式 | 对使用结果有帮助的形式、结构、长度或规格 | 不知道输出一段文案、表格、代码补丁还是图片 |
| 验收与验证 | 如何判断完成、检查事实或处理无法确认的内容 | 只有“做到最好”，没有相关检查条件 |

一个要求可以对多个维度有作用，如“120 字以内”同时影响输出形式和验收；解释各维度判断，不能把同一小缺口当成多个独立严重错误。题干本身的资料不等于用户已传给目标模型；如果用户明确引用“上面的活动资料”，且这些资料在目标对话中可见，应当计入有效上下文。

建议反馈格式：

```text
提示词练习评分：X/20（主观反馈；实际输出：未实测 / 已提供）
目标：X/4 — 原文或缺项依据
背景与资料：X/4 — 原文或缺项依据
约束：X/4 — 原文或缺项依据
输出形式：X/4 — 原文或缺项依据
验收与验证：X/4 — 原文或缺项依据
有效的一处：具体表达及其作用
这轮先改：1—2 个最有影响的点
请提交下一版；或按用户要求给参考版本。
```

有实际输出时另列验收结果：已满足、未满足、无法判断。不要把未实测项目写成通过。

## 四个领域

### 写作

检查读者与渠道、必须保留的事实、语气、篇幅和行动目的。风格用能辨识的表达，例如“给同学的微信群通知，亲切简洁”，不要把“高级感”“专业”当成充分约束。根据材料检查捏造福利、误写时间地点和遗漏行动信息。

### 研究

区分“只分析给定材料”与“联网查资料”。检查问题范围、来源和时间边界、事实与推断的区分、未知的处理。若资料不足，合格输出可以写未知，不能为了完整性填数字。真实引用必须能核验；只点评时指出验证方法即可，不自动联网。不能从文本声称已经核实最新资料。

### 设计与生图

检查主体、数量、用途、构图、材质、光照、背景和对当前任务有用的限制。修改图像时需要明确保留内容与改动范围，不能假设已经看过未提供的参考图。不要要求所有生图模型都支持相同参数或负面提示词语法；用户指定工具后再适配。提示词评价不能代替看图：实际检查主体完整度、布局、材质、文字和修改是否符合要求。

### 编程与 Agent 协作

检查已有代码或文件上下文、具体行为、修改范围、复现步骤和测试条件。把“实现功能”与“提交、推送、部署”分别看作动作；练习文本不授予执行权限。避免“修好所有问题”“顺便重构全站”。用户没提供环境时可以评价描述并指出缺项，不编造文件、接口或测试结果。

## 常见误区

| 误区 | 反馈重点 |
| --- | --- |
| 提示词越长越好 | 删去无助于本题的角色、术语和重复要求 |
| 好提示词有唯一标准答案 | 比较不同表达能否满足相同验收条件 |
| 改稿分数高就一定效果好 | 用实际输出和同条件对比验证 |
| 一次成功代表稳定成功 | 用有代表性的不同输入复测，再讨论稳定性 |
| 给大量修改意见就能快点学会 | 每轮先练最重要的 1—2 项 |
